🌀 Loop Attention 与 GPT-6 Astra

当 Transformer 学会“转圈”：不加参数光靠在权重里“多绕几圈”，究竟是突破计算瓶颈的终极解法，还是一场华丽的空转？

目录：一、引言 · 二、坐标 · 三、Loop Attention · 四、GPT-6 Astra 与循环深度 · 五、两者的架构关系 · 六、争议与未来 · 七、为什么开发者要懂 · 八、常见误区 · 九、总结

一、引言

先问几个听起来很简单、实际上没那么简单的问题:

  • 一个 40B 参数的模型,跑两遍 Loop,等于多少层?答案是 160 层——80 层 × 2 次循环。参数没变,计算深度翻倍了。这听起来像魔术:不加参数,光靠"多跑几圈",模型的有效深度就能凭空拉长——我们是在为"转圈"付智商税吗?
  • 如果模型已经在第一圈"想歪了",第二圈是在纠正错误,还是在错误方向上越转越深?循环架构的核心假设是"多算几轮总能算得更好",但一个错误的初始状态经过多次迭代,可能不是收敛到正确答案,而是收敛到某个错误的吸引子——这类似于人类的"确认偏误",越思考,越坚信自己的错误判断。
  • 一个 3.5B 参数的小模型,转足够多圈,能打出 50B 大模型的成绩——凭什么?2025 年的一篇论文给出了这个令人震惊的结果:参数差了 14 倍,能力却打平了。如果这是真的,那我们过去几年疯狂堆参数的意义何在?

这些问题指向同一个方向:Loop Attention 和循环深度(Recurrent Depth),正在改写 Transformer 的基本运行规则——用"时间"换"参数",用"循环"换"深度"。

二、坐标

Looped Transformer 是"测试时算力"这条线上的架构级新答案。理解它在整个知识体系里的位置,要先划清几条边界:

概念关注的问题跟本文的区别
Frontier·Long Thinking 让模型"想得更久",用思维链 token 换质量——但代价是上下文占用与可见推理的水涨船高 循环深度走的是同一条主线的另一条岔路:把"想得更久"从"吐更多字"搬到"单次前向里转更多圈"——No-CoT 测试正是对 Long Thinking 范式的直接挑战
Frontier·Inference Scaling 推理时算力和效果提升之间的定量关系 循环深度是这个定量关系的新自变量:老曲线画的是"token 数 × 准确率",新曲线画的是"循环圈数 × 准确率"——谷歌"k 层循环 L 次 ≈ k×L 层"的结果就是这条新曲线的第一批数据点
Frontier·Flash Wars 三家 Flash 用线性/稀疏注意力把"每个 token 的成本"打下来 方向互补:Flash Wars 省"宽度"(每个 token 花多少算力),循环深度省"深度"(每层参数买多少次有效计算)——两条路线最终可能在同一颗模型里合流
Frontier·DFlash2 解码层加速:让投机解码每轮验证多通过 token DFlash2 在"生成之后"提速,循环深度在"生成之前"让计算更值——两者叠加时,循环模型的每圈计算同样能被块扩散草稿器并行验证
Foundation·Attention/Transformer Transformer 底层机制:残差流、注意力、层数与表达力的关系 本文挑战的正是"层数 = 表达力"这条默认公理——Loop Attention 的门控融合和循环块的权重共享,都是在这个底层机制上开的口子

一句话理解本文的位置:它讲的不是又一个更快或更便宜的模型,而是一次对 Transformer 运行规则本身的改写——计算深度第一次变成了可以和参数量解耦的自由变量。

三、Loop Attention：让注意力“转起来”

3.1 传统 Transformer 的局限

传统的 Transformer 像一个只能走一遍的高楼，数据从第一层一路爬到最后一层，做完固定次数的运算，吐出下一个 Token。你想让它推理得更深？那就只能把楼盖得更高、参数堆得更大。

代价是什么？极其高昂的算力和显存开销。

3.2 Loop Attention 的核心机制

Loop Attention 换了一个极其暴力的思路：让它转起来。

信息不再是单向穿过网络一次，而是把同一组 Transformer 层反复循环使用。第一圈算出的隐藏状态，直接送回起点继续加工，转上好几轮，最后才吐出结果。它就像一段盘旋向上的楼梯——还是那几级台阶，但只要多绕几圈，照样能到达顶层。

具体到注意力计算层面，Loop Attention 的流程是这样的：

  • Loop 0（第一圈）：执行标准的全局注意力，并把计算出的 K、V 矩阵存入缓存。这一圈的作用是建立“全局记忆”。
  • Loop 1+（后续圈）：同时进行两种注意力计算：
    • 局部注意力：用当前圈的 Q、K、V 计算当前窗口内的注意力；
    • 全局注意力：用当前圈的 Q，去查询第一圈缓存下来的全局 K、V。
  • 门控融合：模型学习一个门控值（gate，0 到 1 之间），动态决定最终输出中全局信息和局部信息的比重。

融合公式为：

output = local_attn + gate × (global_attn - local_attn)

这个 gate 是基于当前圈的 Q 计算出来的——每个 token 都可以根据自己的状态，决定自己更需要全局语境还是局部细节。

3.3 代价与争议

但这套机制并非没有代价。对于一个 40B 模型，loop_num=2 意味着：80 层 × 2 次循环 = 每前向传播 160 层操作。算力消耗翻倍了，参数没变。

更关键的问题是：多转几圈，真的能多算出东西吗？

来自阿里及合作高校的研究团队发现了一个尴尬的现实：第一个 core loop 更新很大，后面两个却迅速缩小。柱子变矮，并不意味着模型少花了算力——矩阵运算和 Attention 照样要跑。这正是 “计算冗余” 的困境：循环次数增加了，后续计算带来的增量却越来越小。

四、GPT-6 Astra：当“循环”登上王座

4.1 什么是循环深度（Recurrent Depth）？

2026 年 9 月 3 日，OpenAI 正式发布了 GPT-6 Astra。The Information 的一篇独家报道揭了它的“老底”：Astra 的秘密武器，是一种叫 recurrent depth（循环深度） 的架构技术。

循环深度的核心思想并不新鲜——它就是 Looped Transformer（循环 Transformer）。普通 Transformer 的一次前向传播中，每层参数只被使用一次；而 Looped Transformer 会把同一组参数重复使用多次。

Astra 的具体实现是 “三段式”架构：

阶段组件运行机制与作用
1. 前奏 Prelude 输入先经过 Prelude 进入潜在语义表达空间。
2. 核心循环 Recurrent Block (R) 同一个 Recurrent Block 反复更新隐藏状态，转上好几圈（思考暗室）。
3. 尾声 Coda 最后由 Coda 解码输出下一个 Token。

中间那个循环块，就是 Astra 的“思考暗室”——所有推理都在里面默默完成，全程不吐一个字。

4.2 “隐形思考”的革命性意义

传统推理模型（o 系列、R1 系列）靠生成更多 Token 来扩展测试时计算——思维链越长，算得越多。但 Astra 走了一条完全不同的路：在潜在空间里“想”，而不是在文字里“说”。

这带来了几个独特优势：

  • 不需要任何 CoT 专项训练数据；
  • 可以在很小的上下文窗口下工作；
  • 能捕捉难以用语言表达的思维类型。

更令人震惊的是 No-CoT 测试的结果。UK AISI 用数学任务测量，在禁止模型输出显式推理的条件下，模型究竟还能稳定解决多难的问题。结果出现了断层式的跃升：

  • GPT-5.6 Sol：只能稳定解决相当于人类约 3.6 分钟完成的数学任务；
  • GPT-6 Astra：直接跃升到了 30.9 分钟。

提升约 8.6 倍，接近一个数量级。与此同时，Astra 写出来的 CoT 反而更短、信息更少。显式推理变少了，但 No-CoT 能力却大幅增强。

这就是循环深度的威力：把过去发生在 CoT Token 里的计算，逐渐搬到了单次前向传播内部。

4.3 代价：看不见的“黑箱”

但硬币总有另一面。“循环深度”的危险在于，它把思考逼进了盲区。

在此之前，业界必须接受一个反直觉的现实：对于推理模型来说，CoT 是模型真正用来打草稿的工作记忆。过去，模型想得再深，也必须从“输出下一个 Token”这个狭窄的漏斗里挤出来——正是这一挤，把抽象的计算逼成了人类能读懂的文字。

而现在，模型在中间的循环块里转了 r 圈，每个 Token 背后就塞进了 r 倍的串行计算。这些计算全程不吐一个字。

OpenAI 自己也承认，Astra 的循环架构“以一种模糊部分或全部 AI 推理（即思维链）的方式工作”。这引发了 AI 安全专家的集体讨伐，甚至一度逼得首席科学家 Jakub Pachocki 亲自下场回应。

五、Loop Attention 与循环深度的关系

那么，Loop Attention 和 GPT-6 Astra 的循环深度是什么关系？

Loop Attention 是“怎么做”——它是一种具体的注意力计算方式，通过两次前向传播（第一次全局缓存，第二次门控融合局部与全局）来实现循环。

循环深度（Recurrent Depth）是“宏观架构”——它指的是模型整体的循环计算流程：Prelude → 共享循环块反复运行 → Coda。

两者的关系是：循环深度是一个更大的筐，Loop Attention 可以是筐里的一种具体实现方式。

事实上，学界已经在这个方向上做了大量探索。比如 Parallel Loop Transformer（PLT）通过“跨循环位置偏移”和“共享 KV 的门控滑窗注意力”，把延迟和 KV 内存都控制在近似常数水平。这正是 Loop Attention 思想在循环深度框架下的演进。

从更宏观的时间线来看，这一切的思想源头可以追溯到 Universal Transformers（UT）——它第一个系统性地把“同一层参数反复应用”作为核心机制。而 2025 年 2 月的论文《Scaling up Test-Time Compute with Latent Reasoning》则直接命名了“recurrent depth”概念，并第一个把它做到了现代规模。

八年演进，终于登上了 GPT-6 Astra 的王座。

六、争议与未来：循环是真突破还是伪命题？

6.1 计算冗余：循环的“阿喀琉斯之踵”

循环架构最大的争议在于 “计算冗余” 。同等算力下，省了参数的循环模型，经常打不过普通 Transformer。原因就在于：循环次数增加了，但后续循环带来的增量信息却越来越少。

阿里的研究团队正是从这里入手，提出了 MeSH 和 SpiralFormer 两套方案。MeSH 解决循环内部怎么管理信息的问题；SpiralFormer 死磕循环之间“以什么精度计算”的粒度问题。目标是同一个：让每一轮算力都花在刀刃上。

6.2 可监控性的代价

另一个争议是 “黑箱化” 。Astra 的思考过程完全“隐身”了。就连 OpenAI 自己都难以看清 AI 大脑的内部运作。OpenAI 首席科学家 Jakub Pachocki 回应称，内部最前沿模型的计算图深度顶多也就 GPT-4 的两倍——但这个回应并没有消除外界的担忧。

循环架构的使用量被刻意限制在“推理仍然可读”的范围内。但问题是：监控性下降是能力跃升的副产品，还是不可逆的代价？

6.3 循环的未来

尽管争议重重，循环架构已经成为下一代高效大模型的候选路线之一。

谷歌在 2025 年的一篇论文给出了一个非常直观的结果：一个包含 k 层、循环 L 次的 Transformer，在不少推理任务上，可以接近拥有 k×L 层的普通模型。参数量没有同步扩大，有效计算深度却被拉长了。

这相当于给“测试时算力”开了一个超频开关。不加参数、不占额外显存，光靠在原有的权重里多跑几圈——拿时间换空间——能力就能越级狂飙。

七、为什么开发者要懂

  • 跟推理成本的关系:循环深度开辟了"不加参数加深度"的第三条路——当上下文预算有限、又想要更深推理时,圈数是一个可以按任务调节的新旋钮;理解它,才能理解下一代 API 里可能出现的"reasoning depth"参数到底在调什么。
  • 跟安全与合规的关系:Astra 的"隐形思考"意味着思维链监控(CoT monitoring)这套目前主流的安全审计手段可能失效——做 AI 安全评估的团队,需要尽快把"内部计算深度"纳入审计视野。
  • 跟模型选型的关系:No-CoT 数据暗示,显式思维链的长度将不再是推理能力的可靠代理指标——"CoT 短"不再等于"想得浅",按思维链长度估算 token 成本和难度的老经验需要重新校准。
  • 跟本地部署的关系:循环架构参数量小、靠时间换深度的特性,天然适合本地与边缘场景——显存受限时,"小模型多转几圈"可能比"大模型转不动"更划算,本地实操专题会接着实测这条路线。

八、常见误区

误区:循环深度就是 CoT 的隐藏版,两者差不多。
真相:CoT 是在输出 token 空间里显式展开推理,每一步都可读;循环深度是在潜在空间里迭代更新隐藏状态,全程不吐字。No-CoT 测试显示两者能力来源正在分叉——Astra 显式 CoT 更短,No-CoT 能力却大涨,说明计算正在从"文字里"搬进"权重里"。

误区:转的圈越多,效果一定越好。
真相:阿里的实测显示第一个 core loop 更新最大,后续圈次的增量迅速缩小——算力照跑,收益递减。不加区分地加圈数,买到的更多是延迟而不是能力;MeSH 和 SpiralFormer 就是为了治这个"计算冗余"。

误区:Loop Attention 和 Recurrent Depth 是同一个东西。
真相:循环深度是宏观架构(Prelude → 循环块 → Coda 的整体流程),Loop Attention 是注意力层的具体计算方式(全局缓存 + 门控融合)。前者是筐,后者可以是筐里的一种实现——把两者混为一谈,会看不懂 PLT 这类"循环框架下的注意力创新"。

误区:循环架构已经全面胜出,堆参数的时代结束了。
真相:同等算力下,省参数的循环模型经常仍打不过普通 Transformer;"3.5B 打 50B"这类结果依赖特定任务与圈数设置。循环是候选路线之一,不是已定的终局——它真正的突破点是"深度与参数解耦"这个自由度本身。

九、总结

从 Loop Attention 到 GPT-6 Astra 的循环深度，我们看到的是一条清晰的技术演进脉络：用“时间”换“参数”，用“循环”换“深度”。

这条路能不能走通，取决于一个核心问题的答案：多转几圈，到底能不能多算出点东西？ 如果能，那循环架构就是下一代大模型的正确答案；如果不能，那它只是一场华丽的“空转”。

从 Astra 在 No-CoT 测试中接近一个数量级的跃升来看，答案似乎倾向于“能”。但计算冗余、黑箱化、可监控性下降等问题，仍是悬在这条路线头上的达摩克利斯之剑。

循环 Transformer 不是让模型从“快思考”变成“慢思考”，而是让模型学会 “在该转的时候转，在该停的时候停” ——但 2026 年的现实是，大多数循环模型还停在“要么不转、要么空转”的两极。Astra 的出现，或许正在打破这个僵局。

💡 当模型学会用潜在空间里的循环计算替代显式文字时，测试时算力（Test-Time Compute）的边界终于从“吐多少字”延伸到了“转多少圈”。
(When models learn to substitute explicit text with recurrent computation in latent space, the boundary of test-time compute finally extends from "how many tokens to generate" to "how many loops to run".)
